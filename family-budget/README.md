# Семейный бюджет

React + TypeScript + Supabase. Совместные доходы и расходы, месячный план-факт, история, CSV-экспорт, приглашения семьи и установка на телефон как PWA.

## Разработка

Node.js 24. `npm ci`, затем `npm run dev`. Без `.env` работает локальный бюджет с сохранением в браузере. Для общей базы скопируйте `.env.example` в `.env` и заполните публичные параметры Supabase. Секретные серверные ключи не используйте.

Для новой базы выполните `supabase/schema.sql` один раз. Существующие базы обновляйте отдельными миграциями. Приложение требует подтверждения email, если оно включено в Supabase.

`npm run check` проверяет типы, lint, тесты и сборку. Тесты изолированы от реального Supabase.

## GitHub Pages

Корневой workflow `.github/workflows/family-budget-pages.yml` публикует интерфейс. В Settings → Pages выберите GitHub Actions. В Variables репозитория задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` (только публичный publishable/anon ключ).

В Supabase Auth → URL Configuration укажите полный HTTPS-адрес публикации в Site URL и Redirect URLs, включая путь и завершающий слеш. Workflow автоматически определяет путь Pages.

## Установка на телефон

Android: откройте сайт в Chrome и нажмите «Установить», если доступно, либо меню ⋮ → «Установить приложение»/«Добавить на главный экран».

iPhone: откройте сайт в Safari → «Поделиться» → «На экран Домой» → «Добавить».

Для совместного бюджета нужен интернет. Каждый участник регистрируется в приложении по email и присоединяется к семье по одноразовому коду. Аккаунты GitHub и панели Supabase участникам не нужны.

Финансовые данные хранятся в Supabase с RLS. Кэш PWA хранит статическую оболочку, офлайн-очереди облачных изменений нет. Резервные копии настраиваются отдельно; CSV не заменяет полную копию.


## Версия 0.4.0

- **Главная:** компактные доходы, расходы, свободная сумма после переводов, накопления, бюджет и крупнейшие категории расходов.
- **Анализ:** графики доходов и расходов за шесть месяцев, динамика категорий, сравнение с предыдущим месяцем. Во вкладке «Операции» — редактирование, история, фильтры и CSV.
- **Бюджет → Лимиты:** месячные лимиты категорий и план-факт.
- **Бюджет → Обязательные:** повторяющиеся платежи с суммой и днём месяца. Отметка оплаты создаёт единственный расход за месяц. Отмена оплаты удаляет связанный расход. Шаблоны изменяются с выбранного месяца до следующего изменения; оплаченные операции сохраняют фактические суммы. День 29–31 в коротком месяце переносится на последний день.
- **Бюджет → Накопления:** несколько счетов с названиями и отдельными балансами, начальные остатки, пополнения, снятия и редактирование движений. Переводы не входят в доходы/расходы. Нельзя снять больше доступного на выбранном счёте и дате. Баланс показан на конец выбранного месяца.
- **Настройки:** название семьи (для владельца), категории (оба участника), участники и приглашения, светлая/тёмная/системная тема. Тема сохраняется на устройстве.

Удаление категории скрывает её для новых операций и сохраняет историю. У категории действующего обязательного платежа сначала нужно изменить привязку платежа. Категории можно восстановить.

Для обновления существующей базы после версии 0.2 примените только `supabase/migrations/20261021110622_budget_features.sql`. `schema.sql` предназначен для пустой базы.

На главной объединён график расходов и бюджета: риска обозначает лимит, красный цвет — превышение. У категорий одинаковая шкала. Подсказки открываются через «?» наведением или нажатием.

Для обновления с 0.3 примените `supabase/migrations/20261021114404_savings_accounts.sql`: прежние накопления переходят в счёт «Накопления». Старые вызовы API остаются совместимыми.

Проверки: 74 теста, включая миграцию с сохранением данных, изоляцию семей, версии записей, повтор оплаты, отмену оплаты, исторические суммы, независимые остатки счетов и анализ. Мобильная вёрстка проверена в изолированном Chrome на ширинах 320–430 px. На самых коротких экранах остаётся вертикальная прокрутка.
