# 0.10.0 — общий лимит расходов

В «Бюджет → Лимиты» можно задать общий лимит выбранного месяца. Рядом с категориями показаны распределённая сумма и остаток. На главной общий порог расходов использует этот лимит; пока он не задан — сумму категорий, как раньше.

- Общий лимит необязателен для существующих месяцев; обновление не меняет финансовые записи и не назначает суммы самостоятельно.
- Лимит 0 допускается. После задания лимита сумма всех категорий, включая архивные, не может его превышать.
- Общий лимит нельзя уменьшить ниже уже распределённого. Сначала уменьшите нужные категории.
- Доходы, накопления и фактические расходы не блокируются этим ограничением: оно касается только распределения плана расходов.
- Копирование прошлого месяца переносит общий лимит, только если в текущем месяце он ещё не задан. Заполненные категории сохраняются. При превышении отменяется вся операция, без частичного копирования.
- Проверка выполняется в интерфейсе, деморежиме и RPC базы. Записи общего лимита, категории и копирование блокируют одну строку семьи до конца транзакции. Это исключает одновременное использование одного остатка двумя участниками; версии защищают от перезаписи чужой правки.

## Обновление базы

После предыдущих миграций примените `supabase/migrations/20261023132054_monthly_budget_limit.sql`, затем публикуйте приложение. `schema.sql` предназначен только для пустой базы.

Новая таблица `monthly_budgets` доступна для чтения только участникам своей семьи через RLS. Запись разрешена через проверяющие RPC. Обычные пользователи и анонимные клиенты не могут менять таблицу напрямую.

## Проверки

Проверяются точность до копейки, нулевой лимит, разные месяцы, изменение распределения, конфликт версий, изоляция семей, атомарное копирование, сохранение существующих данных миграцией и сценарий формы. Параллельные подключения не моделируются PGlite; сериализация обеспечена общим `SELECT ... FOR UPDATE` перед чтением сумм во всех трёх RPC.

## Откат

Можно вернуть интерфейс 0.9.2, сохранив миграцию и заданные общие лимиты в базе. Сервер продолжит запрещать превышение, но старый интерфейс не умеет менять общий лимит. Финансовые данные и новую таблицу при откате не удалять.
